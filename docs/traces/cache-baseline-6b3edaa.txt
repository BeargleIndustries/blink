DECISION: gate FAILED for the shipping configuration -> NOT SHIPPED.

A "Fast mode" toggle was implemented and then reverted (the implementation is in
772cc97, the revert in the commit that follows it; this file is re-landed as
evidence). A user-facing control that provably does nothing on Blink's flagship
<=4-step models fails Principle 1 more than a 25.8% gain on 20-step models
justifies, and the human-eye quality comparison was never performed.

The human-eye quality gate remains UNPERFORMED. It must be done before anyone
enables spectrum in any form.

FOLLOW-UP: on a >=20-step model (Flux dev, SDXL) the speed gate passes
comfortably. The right shape is automatic enablement keyed off the step count --
on when steps exceed spectrum_warmup_steps, off below -- after that quality
check. Not a user-facing toggle, and not a global flip.
